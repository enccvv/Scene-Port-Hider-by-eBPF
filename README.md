# NetWhitelist eBPF Firewall

Outbound whitelist firewall for KernelSU, enforced in the kernel with eBPF
cgroup hooks. Every outbound TCP connect and UDP send is checked against a
rule table held in BPF maps; anything that does not match a whitelist rule is
rejected by default.

Built for the Meizu 21 Pro running Android 16 / KernelSU on
`6.1.25-android14-11-maybe-dirty` (BTF: `btf/vmlinux.btf`).

## How it works

- The `wl_loader` daemon loads `whitelist.bpf.o` and attaches four programs to
  the root cgroup v2 (`/sys/fs/cgroup`):
  - `cgroup/connect4`, `cgroup/connect6` - outbound TCP/UDP connection attempts;
  - `cgroup/udp4_sendmsg`, `cgroup/udp6_sendmsg` - datagram sends on
    unconnected UDP sockets (covers `sendto` on sockets that never call
    `connect`).
- Rules are stored in the `rules4` / `rules6` BPF maps, populated from
  `whitelist.conf`. Writing a new config and sending `SIGUSR1` to the loader
  rebuilds the maps in place - no reboot, no re-attach.
- The default verdict is **deny**. `DEFAULT_ALLOW=1` flips it to allow.
- Loopback traffic (`127.0.0.0/8`, `::1`) is always allowed.
- Per-app control: `UID_MODE=1` restricts filtering to the UIDs listed in
  `ONLY_UIDS`; `BYPASS_UIDS` always bypasses the firewall.
- ICMP ping cannot be seen by the connect/sendmsg hooks, so ping rules are
  enforced separately with `iptables`/`ip6tables` by `whitelist_start.sh`.

## Features

- Kernel-enforced whitelist (no app can escape it by not using the expected
  API).
- Hot reload: edit `whitelist.conf`, send `SIGUSR1`.
- ICMP echo whitelisting via iptables, self-healing daemon.
- KernelSU Manager WebUI page for editing rules from the phone.
- Kernel BTF fingerprint check at install time.

## Requirements

- KernelSU-managed device with a kernel exposing BTF
  (`/sys/kernel/btf/vmlinux`).
- The module is built for the target kernel. Rebuild for other devices/kernels
  using their BTF.

## Build

Local build (requires Android NDK r25c and a libbpf checkout):

```sh
export ANDROID_NDK=/path/to/android-ndk-r25c
export LIBBPF_SRC=/path/to/libbpf
bash tools/build_from_btf.sh     # uses btf/vmlinux.btf from the repo
```

Build straight from a connected phone:

```sh
bash tools/build_for_connected_device.sh
```

The scripts emit `netwhitelist_module.zip`.

## Install

1. Flash `netwhitelist_module.zip` in KernelSU Manager.
2. Reboot.
3. Verify the loader is running:

```sh
su -c 'cat /dev/netwhitelist_loader.pid'
su -c 'cat /data/adb/modules/netwhitelist/whitelist.log'
```

## Configuration

Rules live in `/data/adb/modules/netwhitelist/whitelist.conf`.

| Key | Meaning |
|-----|---------|
| `DEFAULT_ALLOW` | `0` deny unmatched outbound (default), `1` allow |
| `UID_MODE` | `0` filter all UIDs (default), `1` filter only `ONLY_UIDS` |
| `ALLOW_LOOPBACK` | `1` always allow loopback (default) |
| `BYPASS_UIDS` | comma-separated UIDs that bypass the firewall |
| `ONLY_UIDS` | comma-separated UIDs filtered when `UID_MODE=1` |
| `RULE4` | `proto\|dst_ip\|port_start\|port_end` (`*` = any IP) |
| `RULE6` | `proto\|dst_prefix\|port_start\|port_end` |
| `ICMP_ALLOW_ALL` | `1` allow all ping (handled by the shell) |
| `ICMP4` / `ICMP6` | ping targets allowed through iptables |

`proto` is `tcp`, `udp`, or `*` (both).

### Default rule set

The shipped config implements 12 rules:

- TCP/UDP 53 (DNS) to any destination;
- TCP/UDP 8081 to any destination;
- TCP/UDP 16001 to any destination;
- TCP/UDP 17000-17001 to any destination;
- TCP/UDP 112.80.130.26:31006;
- TCP 443 to `110.242.70.69`, `110.242.70.68`, `153.3.237.117`,
  `180.101.52.165`, `157.0.146.158`;
- IPv6 TCP/UDP 53 to `2000::/3`;
- ping to `106.55.91.128` (iptables).

Everything else is denied.

### Hot reload

```sh
su -c 'kill -USR1 $(cat /dev/netwhitelist_loader.pid)'
```

or, after editing the file:

```sh
su -c 'sh /data/adb/modules/netwhitelist/webui_ctl.sh reload'
```

## WebUI

KernelSU Manager shows a "NetWhitelist" entry with a configuration page
(`webroot/index.html`). The page reads/writes `whitelist.conf` through
`webui_ctl.sh` and triggers a reload; all operations are local to the device.

## Uninstall

Remove the module in KernelSU Manager, or run the uninstaller. The loader is
stopped and its programs are detached from the cgroup.

## Limitations

- The cgroup hooks apply to sockets created in the cgroup; they do not filter
  packets already in flight or traffic generated by the kernel itself.
- ICMP is handled with iptables rather than eBPF.
- `UDID`/`BYPASS` semantics apply per-UID; multi-user app UIDs
  (`u0_aXYZ`) resolve to their numeric UID.
- Only arm64 targets are built.
